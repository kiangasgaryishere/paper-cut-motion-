# از اسکریپت تا ویدیو با Codex

راهنمای سادهٔ شروع با اسکیل **Opuscar Short Video Director**؛ برای کسی که تجربهٔ کدنویسی ندارد.

[دانلود عکس مراحل](https://raw.githubusercontent.com/kiangasgaryishere/paper-cut-motion-/main/downloads/opuscar-skill-quickstart-fa.png) · [دانلود اسکیل ZIP](https://raw.githubusercontent.com/kiangasgaryishere/paper-cut-motion-/main/downloads/opuscar-short-video-director.zip)

این اسکیل به Codex روش کارگردانی، طراحی و ساخت ویدیوی کوتاه را می‌دهد. مرجع اصلی آن **Lemo Opuscar** است و تخصصش ریلز آموزشی و داستان‌محور برای زبان‌آموزهاست. خود اسکیل اسکریپت نمی‌نویسد؛ متن ویدیو باید از قبل آماده باشد.

## قبل از شروع چه لازم است؟

- حساب GitHub و دسترسی به Codex در محیطی که بتواند فایل، ابزار و پروژه اجرا کند.
- اسکریپت آماده؛ یعنی متن دقیق چیزی که قرار است در ویدیو گفته یا نشان داده شود.
- فایل صدای گوینده، اگر آماده است. اگر نیست، در بریف مشخص می‌کنید چه کسی آن را آماده کند.
- چند تصویر یا ویدیوی مرجع، اگر سلیقهٔ مشخصی دارید. داشتن لوگو، عکس یا فوتیج اجباری نیست.

اسکیل «دستور کار» است؛ خودش ابزار تولید تصویر، حساب سرویس صوتی یا اعتبار API به شما نمی‌دهد. امکانات محیط باید در شروع بررسی شوند. برای تولید نریشن با یک سرویس پولی، مجوز و دسترسی جدا لازم است؛ برای استفاده از ویس آماده، نیازی به انتخاب سرویس تولید ویس نیست.

## ۱. در GitHub یک مخزن بساز

مخزن یا **Repository** همان پوشهٔ آنلاین پروژه است؛ فایل‌ها، نسخه‌ها و تغییرات آنجا نگهداری می‌شوند.

۱. وارد [GitHub](https://github.com/) شو و **New repository** را انتخاب کن.

۲. یک نام ساده مثل `my-reel-studio` بنویس.

۳. اگر پروژه نباید عمومی باشد، **Private** را انتخاب کن. عمومی‌کردن پروژه برای استفاده از اسکیل لازم نیست.

۴. گزینهٔ افزودن **README** را فعال کن تا مخزن از ابتدا حداقل یک فایل داشته باشد.

۵. **Create repository** را بزن. نشانی مخزن را نگه دار؛ شبیه `github.com/your-name/my-reel-studio` است.

## ۲. مخزن را در Codex انتخاب کن

۱. وارد بخش Codex شو؛ مثلاً از [صفحهٔ Codex](https://chatgpt.com/codex).

۲. اگر حساب GitHub متصل نیست، اتصال GitHub را انجام بده. دسترسی همین مخزن را بده؛ لازم نیست بی‌دلیل به همهٔ مخزن‌ها دسترسی بدهی.

۳. در بخش انتخاب مخزن یا ساخت محیط کار **Environment**، مخزن جدید را انتخاب کن. شاخهٔ اصلی معمولاً `main` است.

۴. اجازه بده محیط آماده شود؛ سپس یک کار یا گفت‌وگو برای همین مخزن باز کن.

نام و جای دکمه‌ها ممکن است با نسخهٔ رابط فرق کند. چیزی که مهم است، انتخاب درست حساب، مخزن و محیط اجرایی است. ساخت مخزن در GitHub به‌تنهایی اتصال به Codex را انجام نمی‌دهد.

## ۳. با این پیام، نصب را به Codex بسپار

نیازی نیست خودت فایل‌های اسکیل را یکی‌یکی جابه‌جا کنی. پیام زیر را کامل کپی کن:

```text
می‌خواهم این مخزن را برای ساخت ویدیوی کوتاه با Opuscar آماده کنی.

اسکیل را از این لینک دانلود کن:
https://raw.githubusercontent.com/kiangasgaryishere/paper-cut-motion-/main/downloads/opuscar-short-video-director.zip

ZIP را بررسی و استخراج کن. پوشهٔ اسکیل را در این مسیرِ همین مخزن قرار بده:
.agents/skills/opuscar-short-video-director/

فایل SKILL.md باید مستقیم داخل این پوشه باشد، نه داخل یک پوشهٔ تودرتوی دیگر.
SKILL.md و راهنمای setup را بخوان و طبق آن عمل کن.

مرجع اصلی ساخت:
https://github.com/lemomo-ai/lemo-opuscar
https://lemomo-ai.github.io/lemo-opuscar/opuscar98/#styles

مرجع افکت صوتی:
https://github.com/wyzowl/sfx-kit

ابزارهای لازم همین محیط را بررسی و وابستگی‌های موردنیاز را نصب کن.
نصب را با یک رندر و خروجی آزمایشی کوچک بررسی کن.
فایل‌های حجیم ابزارها، کش، مدل‌ها و اطلاعات محرمانه را وارد Git نکن.

یک اسکریپت آماده‌سازی قابل‌تکرار به نام setup.sh در ریشهٔ پروژه بساز؛
اگر چنین فایلی وجود دارد، ابتدا آن را بررسی کن و کارهای قبلی را خراب نکن.
بگو برای اجراهای بعدی چه دستوری را در Setup script محیط Codex بگذارم.
تغییرات نصب را ذخیره کن و اگر این محیط با Pull Request کار می‌کند، برای بررسی آماده‌اش کن.

فعلاً ویدیو تولید نکن. در پایان بگو چه چیزهایی آماده‌اند و چه چیزی واقعاً کم است.
```

اگر محیط نمی‌تواند ZIP را مستقیم دریافت کند، آن را از لینک بالا دانلود و در همان گفت‌وگو ضمیمه کن؛ یا استخراجش کن و پوشهٔ اسکیل را در مسیر گفته‌شدهٔ مخزن قرار بده. سپس از Codex بخواه دستورهای داخل `SKILL.md` را بخواند. صرفاً نوشتن نام اسکیل بدون وجود فایل‌هایش، نصب محسوب نمی‌شود.

## ۴. آماده‌سازی محیط را برای دفعات بعد نگه دار

نصب در یک گفت‌وگو لزوماً به معنی آماده‌بودن تمام محیط‌های بعدی نیست. Codex باید در هر اجرا ابزارهای موجود را بررسی کند.

بعد از اینکه Codex اسکریپت آماده‌سازی را ساخت:

۱. در تنظیمات همان **Environment**، بخش آماده‌سازی یا **Setup script** را پیدا کن.

۲. دستور پیشنهادی خود Codex را ثبت کن. اگر فایل واقعاً در ریشهٔ مخزن با همین نام ساخته شده باشد، معمولاً دستور ساده‌ای مثل زیر خواهد بود:

```bash
bash setup.sh
```

۳. اگر دانلود وابستگی‌ها مسدود بود، از Codex بخواه دقیقاً دامنه یا دسترسی لازم را مشخص کند و آن را از تنظیمات محیط مجاز کن. برای نصب GitHub، npm، Python و مرورگر ممکن است دسترسی شبکه لازم باشد؛ همهٔ محدودیت‌ها را بی‌دلیل خاموش نکن.

۴. از Codex بخواه آماده‌بودن ابزارها و امکان رندر را دوباره بررسی کند. پیام «نصب شد» به‌تنهایی جای خروجی آزمایشی را نمی‌گیرد.

مسیر `.agents/skills/` برای نگهداری اسکیل در همین پروژه است. نصب شخصی در مسیرهایی مثل `~/.agents/skills/` روش دیگری است؛ برای شروع این راهنما لازم نیست سراغ آن بروی. شیوهٔ شناسایی مهارت‌ها به محیط/نسخهٔ Codex هم بستگی دارد؛ اگر خودکار شناسایی نشد، مسیر دقیق `SKILL.md` را به آن بده تا بخواند.

## ۵. تغییرات نصب را ذخیره کن و گفت‌وگوی تازه باز کن

اگر محیط گزینهٔ **Create PR / Pull Request** نشان داد:

۱. تغییرات را بررسی کن: باید شامل فایل‌های اسکیل و آماده‌سازی پروژه باشند؛ نه رمزها، فایل‌های خصوصی یا کتابخانه‌های حجیم.

۲. Pull Request را باز کن و **Merge** کن تا فایل‌ها وارد شاخهٔ اصلی شوند. Merge یعنی تغییرات بررسی‌شده را وارد نسخهٔ اصلی پروژه کنی.

۳. اگر محیط روش ذخیرهٔ دیگری دارد، همان روش را انجام بده؛ هدف این است که نصب در شاخهٔ مورد استفادهٔ کار بعدی وجود داشته باشد.

۴. یک گفت‌وگوی تازه روی همان مخزن و شاخهٔ اصلی باز کن. این کار کمک می‌کند فایل‌های ذخیره‌شده و مهارت‌ها در شروع کار جدید بارگذاری شوند.

برای بررسی می‌توانی بگویی:

```text
قبل از شروع، بررسی کن این فایل در پروژه وجود دارد و آن را بخوان:
.agents/skills/opuscar-short-video-director/SKILL.md

بگو اسکیل و ابزارهای موردنیاز آماده‌اند یا چه چیزی کم است.
هنوز تولید ویدیو را شروع نکن.
```

## ۶. اسکریپت، ویس و رفرنس‌ها را بفرست

اسکریپت را در پیام بگذار یا به صورت فایل متنی مثل `script.md` ضمیمه کن. ویس آماده را با کیفیت اصلی در قالب MP3 یا WAV بفرست. رفرنس‌ها می‌توانند عکس، ویدیو یا لینک باشند؛ بگو از هرکدام چه چیزی را دوست داری، مثلاً بافت، رنگ یا ریتم.

همراهشان این موارد را اگر می‌دانی بنویس:

- موضوع، مخاطب و هدف ویدیو؛ برای آموزش زبان، سطح زبان‌آموز و زبان/لهجهٔ هدف.
- استایل دلخواه یا اینکه می‌خواهی Codex از Opuscar پیشنهاد بدهد.
- زبان زیرنویس و مجازبودن مثال‌های انگلیسی/زبان هدف روی تصویر.
- موسیقی می‌خواهی یا فقط افکت صوتی.
- خروجی ریلز اینستاگرام است یا قالب دیگری.

اگر ویس آماده نیست، این موضوع را صریح بگو. نریشن باید قبل از زمان‌بندی نهایی آماده شود. اسکیل خودش متن تازه نمی‌نویسد یا متن تو را بی‌اجازه تغییر نمی‌دهد.

## ۷. پرامپت شروع پروژه را بفرست

این پیام را همراه فایل‌ها کپی کن و جاهای داخل کروشه را عوض کن:

```text
از $opuscar-short-video-director استفاده کن.
اگر اسکیل خودکار شناسایی نشد، فایل زیر را بخوان و طبق آن جلو برو:
.agents/skills/opuscar-short-video-director/SKILL.md

اسکریپت آمادهٔ من ضمیمه است. آن را بدون اجازه بازنویسی نکن.

مخاطب: [مثلاً زبان‌آموز فارسی‌زبان سطح A2].
هدف: [مثلاً یادگیری چند فعل در قالب یک داستان].
خروجی: ریلز عمودی اینستاگرام، ۱۰۸۰×۱۹۲۰.

اول فایل‌ها را بررسی کن و فقط سؤال‌های مهمِ بی‌پاسخ را بپرس.
از من بپرس تولید کامل می‌خواهم یا بخش‌های ۱۰ ثانیه‌ای و چقدر می‌خواهم درگیر باشم.
پیش از تولید، استایل، استوری‌بورد، تصویر هر نما، حرکت دوربین، متن و زمان صداها را مشخص کن.
چند فریم نمونه نشان بده. کار ساده، هنرمندانه و خوانا باشد؛ تکنیک‌های سینمایی گزیده استفاده شوند.
```

**دو انتخاب را جدا مشخص کن:**

| انتخاب | گزینه‌ها |
|---|---|
| روش تولید | بخش‌های ۱۰ ثانیه‌ای یا تولید کامل |
| میزان مشارکت | بررسی هر مرحله، بررسی تصمیم‌های مهم، یا واگذاری اجرای مستقل |

پیشنهاد برای شروع: بریف و جهت هنری را با هم بررسی کنید؛ بعد از تأیید طرح، Codex اجرا را مستقل جلو ببرد. می‌توانی در طول پروژه نظرت را تغییر بدهی.

## ۸. قبل از تولید، طرح را بررسی کن

لازم نیست اصطلاحات سینمایی بلد باشی. ببین Codex واضح توضیح داده است یا نه:

- هر نما چه چیزی را نشان می‌دهد و به کدام جمله مربوط است؟
- در ۵ تا ۶ ثانیهٔ اول چه چیزی توجه مخاطب را جلب می‌کند؟
- دوربین کجا می‌رود و هر ۳ تا ۴ ثانیه چه اتفاق معناداری رخ می‌دهد؟
- عنوان، مثال آموزشی و زیرنویس کجا هستند و آیا خوانا می‌مانند؟
- کدام افکت صوتی، چه زمانی و برای چه اتفاقی شنیده می‌شود؟
- پایان و دعوت به اقدام چگونه نمایش داده می‌شوند؟

استوری‌بورد یعنی نقشهٔ نماها و اتفاقات ویدیو. فریم نمونه یعنی تصویر واقعیِ پیشنهادی برای ظاهر کار. فقط یک توضیح کلیِ استایل، جای این دو را نمی‌گیرد.

اگر در حالت «بررسی تصمیم‌های مهم» هستی و طرح را پسندیدی، می‌توانی بگویی:

```text
بریف، جهت هنری، استوری‌بورد، فریم‌های نمونه و طراحی صدا را تأیید می‌کنم.
طبق روش تولیدی که انتخاب کردیم جلو برو.
برای تصمیم‌های اجرایی معمول متوقف نشو؛ فقط برای تغییر مهم در متن، ویس، هزینه یا جهت هنری هماهنگ کن.
```

اگر اجرای مستقل را انتخاب کرده‌ای، اسکیل باید همچنان برنامهٔ کامل داشته باشد، اما لازم نیست برای تأیید هر مرحله منتظر بماند.

## ۹. تولید و اصلاح را با زمان دقیق جلو ببر

در حالت ۱۰ ثانیه‌ای، هر بار نسخهٔ متصل دریافت کن: ابتدا ۰ تا ۱۰، بعد ۰ تا ۲۰ و همین‌طور ادامه. صدای گوینده و زیرنویس نباید در اتصال بخش‌ها تکرار یا جابه‌جا شوند.

برای بازخورد، به جای «جذاب‌ترش کن»، زمان و تغییر مشخص بده. نمونه:

```text
در ثانیه‌های ۱۲ تا ۱۶، تصویر با جمله هم‌خوان نیست؛ یک نمای مرتبط‌تر بساز.
در ثانیهٔ ۲۷، صدای قیچی واضح‌تر شود، ولی کلمهٔ گوینده را نپوشاند.
عنوان بالای صفحه با تصویر فاصله داشته باشد.
بقیهٔ بخش‌های تأییدشده را حفظ کن و نسخهٔ متصل جدید بده.
```

برای ادامهٔ بخش بعدی:

```text
این بخش تأیید است. بخش ۱۰ ثانیه‌ای بعدی را بساز و نسخهٔ کامل متصل از ابتدا تحویل بده.
```

برای تغییر به تولید کامل:

```text
از اینجا به بعد باقی ویدیو را تا پایان کامل کن؛ دیگر هر ۱۰ ثانیه برای بررسی متوقف نشو.
متن و جهت هنری تأییدشده را حفظ کن و نسخهٔ نهایی را بررسی کن.
```

## ۱۰. فایل نهایی را دریافت و بررسی کن

از Codex فایل MP4 و لینک دانلود قابل‌استفاده بخواه. خروجی پیش‌فرض این اسکیل **عمودی ۹:۱۶، ۱۰۸۰ پیکسل عرض و ۱۹۲۰ پیکسل ارتفاع، ۳۰ فریم** است. برای انتشار عمومی یا ذخیره در یک مخزن عمومی، جداگانه تصمیم بگیر؛ لازم نیست ویس و فایل‌های خصوصی را عمومی کنی.

فایل را روی موبایل ببین و بشنو:

- متن خوانا و از دکمه‌ها و نوشته‌های اینستاگرام دور است؟
- نریشن و زیرنویس هماهنگ‌اند و مثال آموزشی فرصت خواندن دارد؟
- افکت‌ها واضح و مرتبط‌اند، اما گوینده به‌راحتی فهمیده می‌شود؟
- شروع، پایان و اتصال بخش‌ها درست‌اند؟

پرامپت تحویل:

```text
نسخهٔ نهایی را از نظر کیفیت تصویر، خوانایی موبایل، هماهنگی زیرنویس، اتصال‌ها و سطح صدا بررسی کن.
فایل MP4 باکیفیت و لینک دانلود بده و بگو چه بررسی‌هایی واقعاً انجام شده‌اند.
اگر امکان گوش‌دادن یا بازبینی کامل نداشتی، همان را صریح بنویس.
```
