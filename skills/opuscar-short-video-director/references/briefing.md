# Briefing without burden

## Read before asking

Inspect the supplied script, narration, brand files and references. Summarize known facts and unresolved decisions internally. Do not use a blank questionnaire as the first response. No mandatory logo, photos or footage: many Opuscar styles can illustrate the script.

Required script gate: ask for the existing script when absent. Never create a new one as a shortcut. If a supplied script is unfinished, identify that and ask whether the user wants to produce the supplied excerpt; do not finish the writing yourself.

## Ask in small groups

Start with up to three high-impact topics, bundling related details. Follow only with material missing information. Offer defaults, not technical vocabulary quizzes.

1. **Outcome and audience:** what should viewers understand/do? Target language, learner level and pronunciation/accent, if educational. Platform, duration and aspect ratio if unclear.
2. **Inputs:** ready narration? User-supplied or authorized TTS of the exact script? Assets/reference videos? Brand colors, fonts, factual sources or mandatory visuals? Ask for actual assets in normal chat if needed; text-only question tools cannot accept uploads.
3. **Look and sound:** named Opuscar style or 2–3 suitable suggestions? Likes/dislikes? Caption language, educational English/other-language examples and title density? Effects-only or music allowed?

Then explicitly ask:

- “Would you like ten-second review increments, or the complete film in one production pass?”
- “How involved would you like to be: review each stage, review the main direction then let me execute, or delegate the whole production?”

These choices are independent. Ten-second reviews may be requested even with otherwise minimal involvement. Explain that cumulative versions will be delivered.

Use the user's current language; do not force a language-selection step if already clear. Do not dump the whole gallery unless requested. Do not ask again for existing answers or authorization.

## Record a useful brief

Populate `brief.json`, then present a short plain-language summary covering goal, learner, script version, narration status, look, text/audio policy, format and review mode. Mention assumptions that materially affect the result. Keep internal tool details out of the product discussion unless they require a real choice.

Do not call a plan approved merely because the user has not answered. Independent mode authorizes normal implementation choices, not changing the supplied script or spending unspecified credits. Record approved direction and later user corrections in `DECISIONS.md`.

## Decision boundaries

The agent chooses camera easing, asset cropping, suitable sound variants, layout corrections and export settings inside the brief. Ask when missing facts affect meaning, a requested style cannot be achieved with the available tools, the script/narration would change, a new cost/service needs authorization, or a direction change is material. Finish concrete reviewable preparation before asking for final publication approval if publication is not already authorized.
